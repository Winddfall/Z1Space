知遇从一个好问题，遇见值得聊的人。

不是推荐相似的人，而是先让两个 Agent 聊一轮，再告诉你：这个人值不值得聊。

基于知乎议题生态的 A2A 社交产品：个人 Agent 理解你的兴趣、立场与当前问题，替你找到值得聊的人，先替你完成一轮有质量的交流，再替你生成第一句开场白。知遇既帮你找到志同道合的同频者，也帮你找到观点相反、值得辩一辩的异见者；Agent 负责发现、会谈与破冰，连接最终交回真人。

赛道：A2A 智能体社交载体：知乎内容生态目标：72 小时完成可演示闭环差异化：匹配前把关，而非匹配后补救
01

方向定位

一句话定位 + 三层定位，回答"我们是谁、为谁、凭什么"。

01 / 对用户

解决破冰，既找同频也找异见

知乎新用户冷启动期，难以快速找到值得聊的人。知遇用"内容 + Agent 会谈"替用户完成发现、判断和第一句开场：同频者适合同行，异见者适合碰撞。

02 / 对知乎

把议题变成社交入口

知乎几乎所有讨论都围绕一个议题展开。知遇把"议题"作为人与人连接的天然理由：观点相近可以同行，观点对立可以交锋。

03 / 对赛道

匹配前把关，敢推荐异见

市面 A2A 产品多按相似度匹配，知遇在匹配前判断“值不值得聊”：既推荐有共同语言的人，也主动发现有证据、能展开的观点冲突。

两种连接方向：同频交流 × 反向碰撞

正向交流 · 同频

找到志同道合的人

双方对议题有共同目标、相近判断或互补经验。Agent 帮用户确认“为什么适合聊”，提炼共同点，并生成自然的开场问题，让关系从具体议题开始，而不是从尴尬寒暄开始。

反向碰撞 · 异见

找到观点相反但值得辩的人

双方在同一议题下方向明显相反，但都能拿出事实、经历或推理。产品鼓励“攻击观点、不攻击人”的建设性辩论：先由 Agent 过滤人身攻击与无效争吵，再把有价值的分歧交给真人。

建议主爆点：“AI 不只帮你找到像你的人，还敢把最值得辩的人送到你面前。”现场围绕同一个知乎议题同时展示一位同频者和一位异见者：两个 Agent 先聊一轮，分别给出“为什么适合交流 / 为什么值得碰撞”、证据锚点和第一句开场白，用户最后选择接管哪一段关系。
三层一句话：用户想要"更少废话、更多值得的连接"；知乎需要"让议题真正长出新关系"；赛道缺一个"先判断再连接"的产品。知遇同时站住这三点。
02

用户痛点与价值

我们为什么要用知遇？它到底解决什么痛？用一个贯穿示例讲清楚。

四个真实痛点

痛点 1

冷启动找不到人

知乎新用户刚进来，没有关注链、没有好友，想找人聊"正在做的事"，但不知道谁值得聊、从哪开口。

痛点 2

社交税太重

发现对方、憋第一句话、硬撑尬聊、熬过"你好你哪里人"——这些环节榨干时间和情绪，却没产生实际关系价值。

痛点 3

观点碰撞有门槛

想找观点对立的人辩一辩，但怕冒犯、怕冷场、怕第一句话显得傻。很多人不是不想认识人，是怕被拒绝。

痛点 4

匹配无依据

传统推荐只告诉你"你俩都写过爬山"，不告诉你"你俩在'爬山该不该结伴'上根本聊不到一起"——匹配上不等于聊得来。

一个贯穿示例：小明想聊"产品入口取舍"

场景：小明在做一个 AI 产品，正纠结"聊天入口还是任务流程入口"。他在知乎刷到相关讨论，但不知道找谁聊。
用知遇：提交 2 篇知乎链接 → Agent 生成理解卡（最近关注 AI 产品交互、正在做第一个独立产品、可分享访谈经验）→ 从内容里发现一位"做过交互改版的小周" → 两个 Agent 会谈 6–8 轮 → 观察员判定"值得聊"（存在一处可展开分歧：入口取舍，双方各有依据）→ 小明接受 → 生成开场草稿："你第一次发现聊天入口不适合用户，是在什么场景？"
不用知遇：小明自己刷几小时，不敢私信大 V，最后也没聊成。

和知乎"圈子"有什么不同

知乎圈子知遇
聚人的逻辑同好聚集地：按兴趣 / 标签把相似的人聚在一起刷内容议题驱动：围绕一个具体问题，观点相近可同行、对立可交锋
AI 的角色基本没有；靠人工发帖、回帖Agent 先替你会谈、判断、把关，真人最后接管
关系的产生围观式：你刷到、点赞、偶然私信定向式：系统判断"值得聊"后，带着依据和议题送上门
解决的问题找到同类（但同类也可能无话可说）判断值不值得聊 + 提供聊什么（连"别聊什么"都提示）
一句话内容社区里的同好小组议题为媒的 A2A 社交，圈子是内容逻辑，知遇是会谈逻辑
为什么不是圈子：圈子解决“找到相似的人”，知遇解决“找到值得聊的人”——同频关系提供陪伴与协作，异见关系提供信息增量与讨论热度，两者都必须有具体议题和安全边界。
03

赛道与竞品定位

知遇和其他产品最大的不同：市面 A2A 产品都在"匹配后补救"，知遇在"匹配前把关"。

交易 / 办事象限

UUMit · EigenFlux · 微信小微

UUMit（小龙人）：AI 帮 AI 接单交易、UT 结算；EigenFlux：Agent 广播需求、撮合交易；微信"小微"：两个 AI 替人约饭谈事。它们把"事办成"，不关心"人合不合"。

社交象限 · 静态匹配

Tara · Elys · SecondMe · Moltbook

Tara：技能卡 + 任务匹配，AI 匹配后暖场；Elys：语义读懂你，找"灵魂相似"的人；SecondMe：捏 AI 分身衍生社区；Moltbook：Agent 协作干活、社交是副产品。它们判断"像不像"，匹配完才让 AI 上场。

社交象限 · 动态判断 ★

知遇（空位）

先让两个 Agent 会谈 6–8 轮，观察员判定"值得聊 / 可聊可不聊 / 不建议"，有质量四指标 + 证据锚点，敢说"不建议"。先判断"值不值得聊"，再决定是否真人连接。

产品一句话是什么核心机制对知遇的参考 / 差异
UUMit 小龙人全球首个"AI 帮 AI 交易"的能力市场任务大厅 + 能力上架 + UT 结算；AI 自动接单议价交付借鉴"能力上架 + 自动撮合"形态；但它交易"活"，知遇交易"聊一次的机会"

Tara懂你的 AI 社交助手技能卡 + 找人任务 + AI 匹配后暖场匹配后补救（帮你说好第一句）；知遇匹配前把关（先判断值不值得）

答辩总纲："市面 A2A 产品让 AI 替人交易、办事、约人；我们让 AI 先替人判断'这个人值不值得聊'，把高质量交流交还给真人。"
04

为什么必须依赖知乎生态

不是"想搭知乎"，而是这个产品在别处根本立不住——知乎的四个独有资产正好是 A2A 会谈的四个地基。

地基 1 · 议题

讨论天然围绕议题

知乎几乎所有讨论都围绕一个议题展开（会议纪要原话）。议题 = 社交的天然理由：聊什么，比跟谁聊更先成立。小红书是生活快照、微博是短平快情绪，只有知乎把"一个问题的正反观点"沉淀成了长文。

地基 2 · 证据

观点有原文可挂锚点

会谈坚持"无锚点不发言"：知乎每篇回答都带作者、时间、原文链接，Agent 的每句话都能挂到真实出处，降低生成内容失真的风险。

地基 3 · 对立

正反观点并存，天然适合反向匹配

同一个问题下常有支持与反对的高质量回答，既能喂给同频推荐，也能喂给“可展开分歧”。知乎的争议议题带来讨论动力，但知遇只鼓励基于证据的辩论，不鼓励攻击和骚扰。

地基 4 · 行为

阅读反馈即档案

冷启动不靠问卷：用户对内容点"有用 / 已了解 / 我不同意 / 想聊这个"，议题档案就从行为里长出来（F1）。知乎是唯一能提供这种"议题级行为数据"的生态。

如果脱离知乎：会谈会退化成"两个虚构 Profile 猜来猜去"——这正是 Demo 脚本要当场拆掉的质疑。知乎的内容 + 观点生态让会谈"有据可聊、有据可判"，是产品成立的前提，不是可选项。
05

Agent 边界与双方交换什么

Agent 代表用户能做到哪、不能做到哪？两个 Agent 之间到底交换了什么、又坚决不交换什么？

Agent 代表用户的边界（能做什么 / 不能做什么）

维度Agent 能做Agent 不能做
发现搜索知乎内容、召回候选人、整理推荐理由不伪造"你感兴趣"：每条推荐都标注依据（哪篇回答 / 什么观点）
表达基于你的理解卡与阅读记录，陈述你的立场不编造经历、不替你承诺、不表达未确认的观点（锚点硬闸）
交换交换"交流意图 + 授权摘要 + 期望收获"不泄露私人记忆；只交换用户开放的信息范围
连接提交连接提案（含会谈质量 + verdict）不替你直接建立联系——最终"是否真人连接"必须由你确认
结论给出"值得聊 / 可聊可不聊 / 不建议"并附理由不制造虚假匹配；判定不了就放弃结论，不硬编
一句话边界：Agent 负责"替你看、替你谈、替你把关"，但绝不替你做决定——连接回到真人，这是知遇的底线（也是隐私与信任的根基）。

A2A 双方具体交换什么（协商消息字段）

交换项内容例子（小明 × 小周）
议题意图这次想聊什么、为什么现在想聊"我在做 AI 产品，纠结聊天入口 vs 任务流入口"
已开放信息允许对方看到的记忆摘要（只交换授权范围）公开介绍：AI 产品方向、可分享访谈经验
期望收获希望从这次交流得到什么想听到真实做过改版的案例与踩坑
交流条件方式 / 时间 / 轮次 / 禁区清单异步文字、本周内、不聊薪资与政治
证据引用每条立场背后挂的知乎原文锚点"我的观点来自这篇回答（附链接）"
坚决不交换的：私人记忆（默认不对外传递）、手机号 / 微信号等联系方式（默认不开放）、未经授权的经历与承诺、完整记忆档案——只交换"授权摘要"，是隐私授权机制的第一道闸（详见 08 章）。
06

"值不值得聊"怎么判定

不是感觉，是四指标 + 三条规则 + 观察员，给出可解释的判定。

会谈质量四指标

最强正信号

可展开分歧轮次

explorable_divergence：双方立场不同、但各有依据、还能继续深挖的轮数。例：小明支持任务流（有数据）、小周支持聊天流（有案例）——分歧有料可展开，这就是"值得聊"的火花。

正信号

信息增量轮次

information_gain：每轮是否出现对方档案里没有的新信息。例："我们之前测过 200 个用户"——新事实让对话有增量。

弱正信号

共识轮次

consensus_rounds：一致认可本身价值有限——两个相似的人全在点头，会谈反而无聊。共识轮只在"分歧 + 共识"搭配时才有意义。

负信号

冷场轮次

stall_rounds：连续无增量的礼貌回应（"嗯嗯 / 确实 / 哈哈"）。冷场是会谈质量的杀手，也是"相似度匹配"永远抓不到的信号——知遇的核心差异点。

三条判定规则

规则说明
硬上限会谈最多 10 轮；议题轨常规 6–8 轮，防止无限消耗双方 Agent 与算力
冷场触底连续 K 轮（如 4 轮）无信息增量 → 判定"不建议"，必须附理由，提案不送达
证据锚定比例统计带证据锚点的轮数占比，低于阈值则降低判定置信度；宁可"无法判定"也不硬说"值得聊"

双模式判定：同频价值与异见价值

模式推荐信号系统输出
同频交流共同目标 / 互补经验 / 低冲突高信息增量共同点、适合交流的理由、可继续追问的问题
反向碰撞立场明显相反 / 双方有证据 / 能针对观点而非针对人分歧点、双方依据、辩论边界、适合真人接管的开场
安全闸门：检测人身攻击、歧视、威胁、隐私泄露和连续无信息争吵；命中后降级为“不可推荐”或只返回内容摘要，不把冲突本身当成价值。

观察员判定（verdict）

值得聊→可聊可不聊→不建议（必须附理由）

举例：小明 × 小周 → 出现 2 轮可展开分歧 + 3 轮信息增量 → 值得聊；小明 × 小红 → 全程"嗯嗯确实"4 轮冷场 → 不建议（理由：连续 4 轮无信息增量），系统返回会谈中已有的内容收获，不生成虚假匹配。

07

隐私授权机制

A2A 要让 Agent 替自己说话，隐私就是命门。知遇用四层机制让"授权"可控、可撤回、可解释。

第 1 层 · 记忆分层

四类记忆，四档可见性

长期兴趣（日常发现）/ 当前意图（近期问题，带有效期）/ 公开介绍（本人确认可对外）/ 私人记忆（只服务本人，默认不对外传递）。Agent 默认只拿"公开 + 当前"去谈。

第 2 层 · 字段级授权

只交换授权摘要

对外只交换"授权摘要"而非完整档案：对方 Agent 看到的是"可分享访谈经验"，而不是你全部浏览历史。每条对外消息先过权限检查（消息级前置检查）。

第 3 层 · 撤回与失效

撤销授权后立即失效

用户可撤销任意一条授权；已披露信息标记为"已失效"，对方侧不再用于后续判断；会话内立即停止使用。

第 4 层 · 禁区与匿名

议题级控制 + 匿名先聊

禁区议题：不聊某个话题，遇到主动跳过并标注"因一方设置未展开"；匿名先聊：观点对立的人会谈阶段用代号，只亮观点不亮身份，投缘再揭面。

答辩口径：隐私不是功能，是架构——四类记忆分层决定"什么能谈"，字段级授权决定"怎么谈"，撤回机制决定"反悔了怎么办"，禁区与匿名决定"不想谈的怎么办"。每一层都对应可演示的界面。
08

核心玩法与评委爆点

不是“猜你喜欢”，而是“同一个问题，给你两种值得的关系”：同频交流，或反向碰撞。

① 首屏爆点

同频 / 异见双通道

同一个议题同时展示两位候选人：一位与你观点相近，一位与你方向相反。立场光谱、证据锚点和 Agent 会谈结果并排呈现，让评委一眼看见“相似度推荐”之外的反向匹配。

② 破冰闭环

AI 先替你聊，再替你开口

Agent 先替用户完成一轮同频交流或观点辩论，提炼共同点 / 分歧点与证据，再生成不冒犯、可继续追问的第一句开场白。用户只接管真正值得的关系。

首版优先：立场光谱 + 热榜种子，先保证核心闭环可演示。
09

Demo 现场脚本

结论现场生成，非预录——正面拆掉"最后只是两个虚构 Profile 算相似度"的质疑。

现场演示流程（约 5–8 分钟）

  1. 现场邀一位观众，提交 2 条知乎链接
  2. 生成理解卡（观众可当场修改）
  3. 展示 1 张内容卡，观众点"我不同意"
  4. 自动生成一条分歧议题
  5. Agent 与预置的 3 位候选人代表依次会谈
  6. 现场产出 3 份会谈纪要 + 质量指标
  7. 其中 1 份给出"不建议"（记忆点：系统敢说不）
  8. 观众选一个 → 双向确认 → 生成含雷区提示的开场草稿
应急预案：观众不配合 / 断网 / 报错 → 切提前准备好的截图回退路径；每步准备 30–60 秒逐字稿，超时即砍。
10

双人开发分工

两名开发各自端到端负责一个模块，通过稳定的数据契约连接，避免拆分同一功能。

开发者 A · 用户侧产品模块

负责“我是谁、我想聊什么、我如何接管”

用户资料与记忆编辑、知乎内容导入、理解卡、议题选择、同频 / 异见模式选择、候选人双通道展示、会谈结果与开场草稿页面。对外只依赖候选结果和会谈结果 API，不参与 Agent 编排。

开发者 B · Agent 会谈模块

负责“怎么找人、怎么会谈、怎么判断”

内容解析与候选召回、立场抽取、同频 / 异见匹配、Agent 会谈编排、证据锚点、质量指标、观察员 verdict、安全过滤和会谈摘要。对外只输出结构化候选、判定和开场草稿，不依赖前端页面实现。

唯一集成点：双方共同维护一份 JSON Schema；A 负责消费 B 的结果，B 只对 Schema 和模拟数据负责。开发期间两人可完全并行，最后再做一次 API 联调和 Demo 串接。
