把用户流程讲清楚

先完成自己的分身，再让 Agent 探索，最后由双方本人决定是否交流。

连接知乎明确授权
→
确认分身保存三段印象
→
添加 Skill也可稍后添加
→
发现并关注人物与依据
→
阅读动态形成交流问题
→
邀请并聊天对方接受后

从账号接入到进入自己的 Space

01用户 A打开网页，查看知乎授权页并同意。
02系统验证账号、同步允许使用的资料；验证失败则返回重试。
03Agent生成三段印象；缺少资料时提示补充，失败时支持重试或手动填写。
04用户 A自由编辑三段；点击保存并继续，服务端成功后进入 Skill 页。
05用户 A添加模板或创建 Skill，也可以点稍后添加。
06系统标记 onboarding 完成，打开发现页；后续访问恢复已保存状态。
分支：未授权不能进入工作区；资料不足可手动完成分身；没有 Skill 不阻断进入。

从一项 Skill 到一个有话可聊的人

01用户 A在我的 Skills 启用并运行“寻找同路人”，或从发现页选择 Skill。
02系统 / Agent记录任务与分身版本，查找候选、生成有依据的推荐理由。
03用户 A查看任务结果，点进人物 B 的主页；决定关注或直接邀请。
04系统关注成功后，将 B 加入站内关注关系，并聚合可用的知乎活动。
05用户 A在关注动态按人 / 活动类型筛选，阅读 B 最近发布、分享或赞同的内容。
06用户 A点击“和 B 聊聊”，该内容与话题进入邀请草稿。
分支：无结果展示空态；不支持的数据类型单独说明；关注只是单向订阅，不代表 B 已同意聊天。

A 发出邀请，B 本人接收并接受

01用户 A从人物或内容打开邀请弹窗，修改 Agent 建议的开场白，主动发送。
02服务端保存 pending 邀请，投递到 B 的站内消息列表，A 看到待确认。
03用户 B登录自己的账号，查看 A 的公开资料、共同话题与邀请文字。
04用户 B接受 → 建立会话；拒绝 → 结束邀请。A 也可在 pending 时撤回。
05A 与 B在同一会话中亲自输入并发送文字，看到对方的消息。
06系统保留消息、共同话题和已读位置；刷新与重连后恢复。
分支：未接受不能发送聊天消息；同一对用户只建立一个会话；模拟接受 / 模拟回复不属于正式功能。
首次进入后的默认落点：进入发现页。再次登录恢复最近访问的有效工作区页面；中途退出新手流程，恢复最近完成步骤。取消授权不生成分身，保存失败不向下一步跳转。

F01

知乎授权与账号接入

连接身份 · 核心功能 P0

让用户明确授权，将知乎公开资料关联到自己的 Z1Space 身份。

入口首次访问；已有用户的“重新连接知乎”。
页面授权页 → 分身生成页；失败时留在授权页。
输出可识别的 Z1 用户、知乎账号映射、授权范围与资料同步结果。

用户操作步骤

  1. 访问 Z1Space，展示独立授权页和用途。
  2. 主动同意后，通过可用的知乎接入方式完成账号验证。
  3. 服务端校验授权结果并绑定账号，随后同步允许读取的资料。
  4. 新用户进入分身创建；老用户按已保存进度恢复。

业务规则与异常处理

规则实现要求
接入方式真实接入依赖知乎 / 黑客松实际提供的账号验证与数据能力。不要把原型的确认勾选当作账号验证。
初始数据优先昵称、头像、个人介绍、回答 / 文章；关注与互动只在接口和授权均允许时使用。不可获取的字段标为 unavailable。
回调与身份校验回调对应的当前授权请求与用户会话；绑定以稳定的外部账号 ID 为依据，不能以昵称区分用户。
授权失败取消、超时、验证失败分别显示可理解原因；保留重试入口，不推进 onboarding。
同步降级账号验证成功但部分材料不可用时，保留成功身份，进入“资料不足”的分身流程；不能冒充完整同步。
再次进入服务端保存最近完成步骤；分身已完成的用户不重复初始化，不覆盖编辑内容。
重新连接 / 撤销失效后停止新同步并提示重连；已建立的 Z1 关系保留。撤销后停止相关任务并按数据使用范围处理衍生索引。

功能完成标准

前置条件操作 / 事件应得到的结果
未同意授权点击主按钮不能发起接入请求。
用户拒绝或回调失败返回页面仍在授权页，可重试，账号状态未变成成功。
同一知乎账号重复登录验证通过复用原用户、分身、Skills 和关系。
只有昵称与简介可用同步完成明确显示资料不足，可继续手动补全分身。
开发交接：前端：授权入口及状态页；后端：账号、会话、授权请求和同步状态；接入负责人：确认真实字段、授权范围及账号验证方式。
F02

Agent 分身与个人主页

认识并表达自己 · 核心功能 P0

把账号表达整理为三段可编辑印象，由用户确认，再形成可被他人理解的主页。

入口首次授权成功；个人主页“编辑分身印象”。
页面分身创建页 / 编辑弹窗 / 个人主页 / 他人主页。
输出一个分身档案、一份用户确认的三段介绍，以及对应的主页。

用户操作步骤

  1. 读取 F01 中可用的本人资料，触发生成任务。
  2. 呈现恰好三段印象和来源提示，用户可以独立编辑。
  3. “保存修改”保存当前版本；“保存并继续”保存成功后进入 Skill 配置。
  4. 个人主页展示最新已保存内容；用户后来仍能编辑、保存或取消。

业务规则与异常处理

规则实现要求
三段结构沿用原型：思考方式、兴趣与实践、交流倾向。标题可固定，正文自由编辑；生成结果必须可追溯到本人资料。
字段校验每段去首尾空白后 8–420 个字符。前后端采用统一字符计数方法；不得仅在前端校验。
保存动作独立编辑草稿与已保存版本。成功反馈后才更新主页；保存失败保留草稿；未保存离开要提示。
用户修改优先用户确认内容优先于生成内容。后续同步或模型运行不自动覆盖；新生成内容只可作为待确认草稿。
资料不足 / 生成失败展示缺失或失败原因，提供重试与手动填写三段的路径。不能生成不存在的工作经历、兴趣或社交意愿。
主页展示昵称、头像、公开介绍、三段印象、添加的 Skills、关注数与已连接数。人数和内容数均来自真实数据，不保留示例数字。首次保存前说明三段印象与公开 Skills 会用于站内主页和人物发现。
Skill 展示本人及他人可见已添加 Skill 的名称、类别与简述；暂停仍展示“已暂停”，移除不再展示。执行结果、完整私人任务目标不默认公开。
他人主页只读公开资料、代表内容和公开 Skills；允许站内关注与邀请。本人看到编辑操作，他人不能修改。

功能完成标准

前置条件操作 / 事件应得到的结果
生成材料可用生成成功输出三个不同维度段落及来源引用；无虚构身份经历。
任意一段为空或超长保存 / 继续阻止提交并定位该段，其他输入不丢失。
用户改写三段并保存刷新 / 再次登录创建页、主页和 Agent 使用的是同一已确认版本。
某 Skill 新增、暂停、移除打开本人及他人主页分别显示、新状态标记、隐藏，数量一致。
开发交接：前端：段落编辑与主页；后端：档案、版本与权限；Agent：依据提取和三段生成。原型保存 / 长度规则沿用，生成与公开边界需要正式实现。
F03

Skill 创建、管理与执行

把意图变为任务 · 核心功能 P0

用户通过模板或自定义，为分身配置“找人 / 找内容”的具体能力并查看运行结果。

入口首次创建分身后的 Skill 页；工作区“我的 Skills”；“让 Agent 再找找”。
页面Skill 初始配置页 / Skill 列表 / 创建编辑弹窗 / 运行状态弹窗。
输出用户拥有的 Skill、一次运行记录，以及人物或内容结果集。

用户操作步骤

  1. 从五个模板添加 Skill，或填写表单创建自己的 Skill。
  2. 保存后同步到个人主页；新用户也可选择“稍后添加”。
  3. 在已启用 Skill 上点击运行，创建服务端任务并展示进度。
  4. 任务完成后查看找人或内容结果；失败可重试，空结果可调整关键词。

业务规则与异常处理

规则实现要求
任务范围第一版支持 people（寻找人）与 content（整理内容）。自定义是配置目标与筛选条件，不执行用户上传代码或任意指令。
模板寻找同路人、每日值得读、观点碰撞、项目搭子、知识补给。模板添加后成为用户实例，可独立修改。
名称与字段名称 1–24 字符、目标 1–500 字符、关键词原始输入 1–100 字符；均去首尾空白。至少一个有效关键词，以空格或中英文逗号分隔。
重复与幂等同一用户同一模板仅一个实例；名称去首尾空白后同名禁止，英文大小写统一比较。并发重复请求也不新增重复项。
公开与私人公开名称、类型、简述及启用状态；完整任务目标 / 关键词 / 结果仅本人可见，避免在他人主页泄露具体需求。
手动执行P0 只需手动运行。一个 Skill 同时最多一个 queued / running 任务，重复点击返回该任务；前端关闭弹窗不取消服务端任务。
执行依据输入已确认分身、Skill 配置与授权材料；先按类型和关键词召回，再整理理由。支持语义检索，但不依赖全站所有 Agent 相互闲聊。
暂停 / 移除暂停禁止新运行；已开始任务允许完成。移除后禁止新运行；未启动的排队任务取消，已运行任务可完成但不再自动替换发现结果。历史记录归档。
结果归属每次运行保存 Skill 与分身版本快照，结果携带 run_id、证据和完成时间；空结果也是成功完成的一种结果，不回填旧结果。
频率“每日一次”为 P1。未接入调度时禁用该选项或标明暂未开放；不能沿用原型仅保存选择却暗示会自动执行。

功能完成标准

前置条件操作 / 事件应得到的结果
尚未添加 Skill点击稍后添加可进入发现页；我的 Skills 和主页出现清楚空态。
创建“寻找摄影同好”并填写摄影关键词保存并运行主页显示实例；结果与摄影相关，不能返回无关预设人物冒充匹配。
双击同一模板 / 运行按钮服务端收到重复请求只创建一个实例 / 一个有效运行任务。
任务运行中关闭弹窗并刷新再次打开任务能恢复真实状态；失败和零结果有明确说明。
暂停 Skill点击运行或直接调用接口均阻止新任务；移除不删除已有关注与聊天。
开发交接：前端：表单与任务反馈；后端：实例、状态和任务队列；Agent：任务执行及结果结构化。每日调度单独排入 P1。
F04

人物发现、关注与知乎动态

从人读到内容 · 核心功能 P0

Agent 带回值得认识的人；用户关注后持续看到这些人的知乎表达和可用互动，并找到聊天切入点。

入口发现同路人 / 探索结果 / 人物主页 / 关注动态。
页面发现页 / 他人主页 / 关注动态 / 内容详情。
输出带依据的人物推荐、站内关注关系、可筛选的活动流与内容详情。

用户操作步骤

  1. 展示初始推荐或某次 Skill 结果；每个人有推荐理由、标签和内容依据。
  2. 点击关注，建立 Z1Space 的单向关系；点击名字进入对方主页。
  3. 关注动态只聚合所关注人的可用活动，按时间倒序显示。
  4. 筛选某个人或发布 / 分享 / 赞同，阅读内容后可邀请相关人物聊天。

业务规则与异常处理

规则实现要求
候选池可连接人物须为已保存分身并完成新手流程的有效 Z1Space 用户，进入候选池前已知晓主页公开范围。未加入的知乎作者最多作为内容来源展示，不自动创建真人分身或开放聊天。
初始发现基于已确认分身和可用资料给出首批结果；没有结果显示添加 / 调整 Skill，不保留“发现 3 人”等固定数字。
推荐卡稳定用户 ID、昵称、头像、公开简介、话题、推荐理由、依据引用、当前关注 / 连接状态。去重并排除本人。
关注含义仅为 Z1Space 站内单向关注。无需对方互关；关注不等于同意聊天，不回写知乎关注关系。
取消关注移除该行为人在关注流中的活动及关注计数；不删除已经建立的聊天，也不自动取消待处理邀请。
三类活动publish：本人发布回答 / 文章；share：本人分享 / 转发内容；upvote：本人赞同内容。实际可提供类型取决于接入能力，不假定全部可用。
行为人与作者行为人是你关注的人，内容作者可能是另一个人。卡片分别显示“谁赞同 / 分享了什么”和“文章是谁写的”，两种身份不得混用。
时间、去重、筛选按 activity.occurred_at 倒序，id 作为稳定次序。以平台活动 ID 或 actor＋type＋content＋事件时间去重；按关注人和行为类型组合筛选。
不可用 / 暂无 / 失败未授权或平台不提供用“暂不支持读取”；已支持但暂无数据用空态；同步失败保留旧内容并标记最近同步时间和重试入口。
阅读与邀请对象可展示全文才打开全文；只有摘要则展示摘要及原文入口。从赞同 / 分享卡片默认邀请行为人，界面清楚写“和谁聊聊”；内容作者需另走人物入口。
点赞与收藏原型已有的站内点赞 / 收藏列为 P1。若实施，本地互动计数与知乎赞同快照分开展示，不把 Z1 的操作加到知乎数字里。

功能完成标准

F05

真人邀请与文字聊天

把连接交回真人 · 核心功能 P0

让用户围绕具体内容或共同话题发起邀请，由接收方同意后开始真实的站内交流。

入口人物卡 / 他人主页 / 内容卡片 / 真人消息列表。
页面邀请弹窗 / 接收方邀请详情 / 会话列表 / 文字聊天页。
输出有状态的邀请、双方确认的唯一会话，以及可持久化的双向消息。

用户操作步骤

  1. 发起方 A 选中 B，Agent 生成开场草稿，A 修改并主动发送。
  2. B 的真人消息中出现邀请；B 查看 A、共同话题和草稿。
  3. B 接受则建立会话；B 拒绝、A 撤回或邀请过期则结束本次邀请。
  4. 已连接的 A / B 自己输入文字并发送，按需使用共同话题与历史内容。

业务规则与异常处理

规则实现要求
邀请条件A 与 B 均为可连接的 Z1 用户且不是本人。无需先关注；关注和聊天同意是独立关系。
草稿与内容草稿必须可编辑，最多 500 字符，去首尾空白后不可为空。关联人物 ID、内容 ID（可选）、话题快照和原文来源。
发送与接收服务端保存邀请，接收方能在列表和详情看到。原型的“模拟对方接受”必须替换成 B 账号自己的接受 / 拒绝入口。
状态与期限pending → accepted / rejected / withdrawn / expired；本版建议默认 7 天到期，作为可配置值。待处理期间同一对用户只保留一个有效邀请。
重复及交叉邀请同方向重复发送复用原邀请；反方向已有 pending 时提示对方已邀请并打开它；已连接时直接进入既有会话。
权限和并发仅接收方可接受 / 拒绝，仅发起方可撤回。接受与撤回并发时以服务端首次有效提交为准；返回最终状态，不产生幽灵会话。
拒绝后的行为不创建聊天，不自动反复邀请；同一对用户拒绝后建议 24 小时冷却，由配置控制。过期 / 撤回后可重新发起。
真人消息每条 1–1000 字符；发送中、已发送、失败可重试。只有会话参与者可读写；顺序由服务端分配，重试用 client_message_id 去重。
记录与未读会话按最后活动排序，展示最后消息和未读数。已读以最后阅读消息序号记录；刷新 / 重连拉取缺失消息。
Agent 接管边界Agent 提供依据和草稿，不替真人发送、承诺或回应。正式运行时移除模拟接受 / 模拟回复控件。音视频、群聊和知乎私信代发不纳入本版。

状态与业务关系

这些状态由服务端维护；按钮文案和页面跳转以服务端结果为准。

账号与同步

not_connected → authorizing → connected

取消 / 失败返回 not_connected；connected 可转 expired / revoked。资料同步另设 pending / syncing / ready / partial / failed，不与身份验证混为一谈。

分身与新手流程

syncing → generating → draft → saved

生成失败可重试或手写；只有三段成功保存才进入 Skills。完成 / 跳过 Skills 后 onboarding=done。

Skill 运行

queued → running → succeeded

failed / cancelled 为结束状态；succeeded 可有 0 个结果。关闭弹窗不取消任务。

邀请状态

pending → accepted / rejected / withdrawn / expired

仅 accepted 创建或返回唯一会话；状态更新需原子校验。重复接受返回同一会话。

消息发送

sending → sent / failed

失败重试复用 client_message_id；sent 表示服务端已接收并落库，不能直接当作对方已读。

单向关注

not_following ⇄ following

关注、邀请、会话为三种独立关系。取消关注不结束会话；接受邀请不自动互相关注。

三个容易混淆的定义

对象成立条件不代表什么
关注A 主动订阅 B 的站内关系。B 不需要互关，也不等于同意聊天。
聊天邀请A 发出邀请，B 尚未决定或已决定。pending 不允许发送普通会话消息。
真人会话B 接受有效邀请后，由服务端建聊。Agent 不自动接管用户发送；站内消息不等于知乎私信。

D03发布、分享、赞同事件是否可读，以及行为时间 / 事件 ID 是否可用。F04类型按能力开关；不把不可读取等同于用户没有活动。
D04内容允许展示全文、摘要还是只允许原文链接。F04按授权范围渲染，保留来源入口。
D05数据同步频率、分页、限额、失效 / 撤销通知方式。F01 / F03 / F04实现重试和缓存；过期数据标明时间，停止越权新读取。
文档采用的产品默认值：邀请 7 天到期、拒绝后 24 小时冷却、每个 Skill 同时最多一个活跃任务，均为本 PRD 的实现建议，并非原型已经具备或知乎平台规定。配置可调整，状态逻辑保持一致。

新用户完整流程一个新用户从真实接入或明确演示接入进入，保存三段，自定义或跳过 Skill，进入工作区。同一账号刷新与重新登录不丢失已确认内容；演示与真实模式标签明确。
真实生成与任务分身依据本人材料生成；Skill 在服务端运行，并能恢复任务状态。每次生成 / 推荐有来源引用；失败、零结果与重试均可复现。
个人主页一致性修改印象、添加 / 暂停 / 移除 Skill 后，本人及他人主页看到正确公开状态。两个账号查看结果一致，私人任务内容不泄露。
关注与动态A 关注 B 后看到 B 的可用活动；筛选、分页、取消关注均符合规则。区分行为人 / 作者 / 活动时间；不支持的类型有明确状态。
两个账号真人通信A 发出邀请，B 在另一会话登录后处理，接受后双方互发文字。无模拟接受 / 回复；服务端记录真实双方、邀请、会话和消息。
异常与权限拒绝授权、资料不足、生成失败、任务失败、邀请失效、消息重试与越权请求均被处理。失败保留必要输入、提供恢复路径；直接请求接口也受权限约束。
响应式与可恢复桌面与手机可完成主路径；刷新不会重建关系或重复发送。键盘可操作表单 / 弹窗；长内容不遮挡主要按钮；服务端持久化。
交给开发同学的一句话：先实现五个主功能的真实数据与状态流转，让两个用户从各自的知乎表达出发，经由 Agent 发现、站内关注和一条有上下文的邀请，完成一次本人参与的文字交流。
